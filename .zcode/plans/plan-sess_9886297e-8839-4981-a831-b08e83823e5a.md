## 简化落地：删除作用域节点，新增纯原语 git.checkout（切换分支）

### 1. 删除作用域机制
- `engine/nodes/build.js`：删除 `git.deployVersion.open` / `git.deployVersion.close` 两个节点。
- `engine/workflow.js`：删除作用域栈、closeScope/unwindScopes、scopeExit 弹栈逻辑与 validateWorkflow 的作用域配对校验；头部执行语义注释同步更新。
- `tools/verify-dryrun.js`：删除作用域相关断言（deployVersion 标志、配对校验、作用域执行/unwind 共 3 项）。

### 2. 新增 `git.checkout`（title：切换分支，版本分类）
- inputs：`repoDir`（folder，必连）、`ref`（string，必连）
- outputs：`original`（string）= 切换前的 HEAD（分支名；detached 时为 hash）
- run：记录当前 HEAD → `git checkout <ref>` → 返回 original。**无 fetch、无自动恢复注册、无错误特殊处理**——ref 不存在/非 git 仓库等情况直接抛 git 错误使任务失败，作为此类工具的已知缺陷保留；恢复由用户显式组合：把第一个 checkout 的 `original` 连到后续 checkout 的 `ref` 即完成切回。
- dry-run：只打日志（将 checkout X），不切换。

### 3. 已保存工作流的迁移
`wf-ls-client.json`（用户已保存）中含有 `git.deployVersion.open` 节点，类型删除后该工作流将校验失败。处理：将其中 deployVersion 节点迁移为 `git.ref`（repoDir/ref 数据与既有连线可保留，功能最接近、且自带任务结束恢复），确保加载校验通过；实现时先读该文件确认具体连线。

### 4. 自检与验证
- verify-dryrun：新增 git.checkout 断言——临时 git 仓库（init + main 提交 + 建 v1 分支）上 ref=v1 切换 → 日志 `main → v1`；再以 original 连第二个 checkout → HEAD 回到 main；不存在的 ref → 任务拒绝。
- `npm run build` 通过（前端零改动，git.checkout 走通用渲染）。
- 浏览器冒烟：全部注册工作流可加载；fs.path → git.getRefs → git.checkout 组合可用。
