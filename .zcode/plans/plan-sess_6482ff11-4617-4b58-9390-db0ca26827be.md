# 基础类型端口内联控件（string/number/boolean）+ 必填语义升级

设计依据已确认：不违背哲学——它是 struct.make 字段模式（端口+控件+连线优先）推广为引擎统一法则，
消灭 string.const 的主要使用场景（string.const 本身按你的决定**保留**——多节点共享一个值、改一处全更新）。

## 语义核心

- **字面量存储**：`node.data.lit = { <端口id>: 值 }`（随图持久化）；
- **优先级**：连线 > 字面量（连线建立时清除该端口的字面量——你定的 boolean“断线双灭”语义即由此来）；
- **必填升级**：required = 必须有**值**（连线或字面量任一满足），不再强制必须有连线；报错文案区分“未连线且未填值”；
- **适用端口**：类型 ∈ string/number/boolean 的输入口（含动态 {{}} 端口与 path.resolve 的 p1..pN）；
  **除外**：struct.make 字段口（fromField——已有字段行控件，双重编辑冗余）、any/struct/ssh 端口。

## engine

1. `engine/nodes/index.js`：getInputs 给 fieldInputs 生成的端口加 `fromField: true` 标志（内联控件与字面量注入都跳过它们）。
2. `engine/workflow.js`：
   - 任务校验：required 判定加 `hasLit = node.data?.lit?.[inp.id] !== undefined`——有字面量即满足（未选入/未连线都不报）；
   - executeTask runNode：连线解析完后，未连线的 string/number/boolean 端口（非 fromField）注入 `coerce(data.lit[id], 类型)`。

## 前端

3. `web/src/types.js` validateTaskSelection 镜像同一规则（有字面量即满足 required）。
4. `web/src/DevNode.svelte` 输入行内联控件（同排右侧，宽 ~110px）：
   - **wired**：disabled 输入框显示 resolveInput 解析值；解析不到（运行时产出）显示“（运行时）”；
   - **string**：text 输入；**number**：数值输入（非法红边，存 Number）；
   - **boolean**：双 radio 按钮「是 / 否」，默认双灭；点一个亮一个（写字面量）；连线建立即清字面量（断线自然双灭）；wired 时禁用并显示连线值状态；
   - string 清空 = 删除字面量（回到“未设置”）；
5. `web/src/App.svelte`：onConnect 建立数据边后清除目标端口字面量。
6. `web/src/app.css`：行内控件样式（紧凑、暗主题）。

## 验证

- verify：required 由字面量满足（无连线）通过；运行时字面量注入 + 连线覆盖字面量；number 矫正；现有“未连线”报错文案更新后仍覆盖。
- `web build` + 重启 3010 + 浏览器冒烟：string 端口直填值→required 星号满足；连线后变 disabled 显示来源值；boolean 双 radio 交互；kids-ledger-prod 打开保存正常（string.const 保留不动）。
- string.const **不迁移不删除**（共享值源）。
