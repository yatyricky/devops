# 连线拒绝提示 + tar.pack 模式重构 + 任务运行状态外框

## 0. 连线问题诊断结论（已查实）

`constr8kt3` 是 Struct 构造器（未存进你这份文件——你最终用 string.const "dist" 连了 p2）。构造器唯一出口是 **struct 类型**，`resolveqj5z2` 的 p2 是 **string**——`struct→string` 被类型契约拒绝，而拖拽中的拒绝是静默的。现行正确连法：构造器 → Struct 析构器 → 字段口 → p2。按你的决定**保持两段式**（未来 selector 的基础），本方案补上拒绝提示。

## 1. 连线拒绝原因提示（App.svelte）

- 把 `isValidConnection` 重构为 `connectionRejectReason(p)`（返回 null = 可连，否则返回原因文案：同节点/类型不兼容 A→B/同四元组重复/顺序边重复）；isValidConnection = `!reason`。
- `onconnectend(event, cs)`：cs.isValid === false 且落在目标 handle 上时，用 cs 的 from/to 信息算出原因并 toast（拖拽中仍不打扰；拖空白处取消不提示）。

## 2. tar.pack 重构（engine/nodes/build.js）

- **widgets**: `entries`（打包条目，list）+ **`excludes`（不打包条目，list，新增）** + prefix。
- **模式**（run 时）：两者都空 → 打包所有（entries=["."]）；仅 entries → 白名单（现状直打包）；仅 excludes → 黑名单（stage 暂存 + 段排除过滤 + 打包暂存全部，复用 makeStageDir/copyTree）；**两者都配 → 报错**（validateWorkflow 节点级检查 + run 时兜底）。
- **输出仅 `archive (string)`**：压缩包完整路径；删除 `archiveName` 出口。
- desc 同步三种模式说明。

## 3. 任务运行状态外框

- **engine/runner.js**: `run.nodeStatus = {}`；ctx 新增 `markNode(id, status)`（写入 + persist）。
- **engine/workflow.js executeTask**: 每节点执行前 mark `running`，成功 `ok`，失败 `failed`（同批失败的各自标记）。
- **index.js SSE**: tick 时 nodeStatus 快照变化 → 发 `{type:"node", nodeStatus}`；断流轮询兜底同样补发。
- **web/src/api.js**: streamJob 处理 `node` 事件（`h.node?.(nodeStatus)`），轮询兜底同步。
- **web/src/store.svelte.js**: ui 增 `runTaskNodes: null`（Set，运行中任务选点集）与 `nodeRunStatus: null`。
- **App.svelte**: doRun 时设 runTaskNodes、清空 nodeRunStatus；LogDrawer.follow 增 onNode 回调透传；loadDoc 切换工作流时清空两者。
- **DevNode.svelte**: 按 ui 状态加 class——不在任务中 `offtask`（半透明灰）、已执行 `st-ok`（绿框）、报错 `st-fail`（红框）、正在执行 `st-run`（绿色虚线跑马灯 outline 动画）；未执行 = 常规。
- **app.css**: 四种状态样式 + marquee keyframes。
