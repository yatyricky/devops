# A. Struct From JSON 加 shape 定义（静态化）→ 出口 = struct_N；B. SSH命令 fullrow + 高亮

## A1. shape 定义（操作方式同 Make Struct，无值列）
- **engine/nodes/input.js fromjson**：widgets 加 `{ key: "shape", label: "Shape（key / 类型）", kind: "struct", shapeOnly: true, default: [] }`；`outputs: []` → `dynamicOutputs: "fromJsonShape"`；desc 更新（JSON 必须是 shape 的子集：允许字段缺失，多余字段/类型不匹配报错；出口类型 = structShape）
- **DevNode struct 字段编辑器 shapeOnly 模式**：`w.shapeOnly` 时隐藏值槽（wired/tri/fval 分支全不渲染，行 = key input + type select + 删除），fieldAdd 不带 value 键——key/type 编辑、删除、＋ 与 Make Struct 完全一致

## A2. 出口与校验（全部静态）
- **rules.js effectiveOutputs** 新分支 `fromJsonShape`：`[{ id: "struct", type: structShape(data?.shape) }]`（空 shape → 纯 "struct"）
- **run 子集校验**（shape 非空时）：shape 逐字段——JSON 缺该键 = undefined 允许（输出对象不含该键）；JSON 有该键但类型 ≠ shape 类型 → 报错「字段 X 类型不匹配（期望 string，实际 number）」；JSON 键 ∉ shape → 报错「多余字段 X: …」；**shape 为空/未配置 → 报错「未定义 shape」**（出口类型必须可推导）。通过后 markNodeOutput 上报 + 返回 { struct: obj }
- **rules.js structSplit 分支** 加第三条回溯路径：上游出口列表中存在形状串出口（fromjson 的 struct:struct_N；兜底通用，不点名类型）→ structFieldsFromShape 解析为字段出口（make 声明序/selector 路径保持在前）

## A3. 验证（verify）
- fromjson run：类型匹配通过 / 类型不匹配报错 / 多余字段报错 / 缺失字段放行 / 空 shape 报错
- 出口：shape=[alias:string] → 出口 type=struct:{alias:string}；**split 回溯 fromjson** → 出口 [alias:string]（你 case 的链路）
- dashboard 编辑期派生（形状串出口解析已有）自动可用
