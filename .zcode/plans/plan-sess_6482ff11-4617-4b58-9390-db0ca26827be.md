# 记住上次打开的 wf + start.cmd 启动前逐路径 git pull

## 一、记住上次打开（显式 lastOpened 字段，不再依赖列表顺序）

现状：open/save 都走 `rememberWorkflow()`（前插 `workflows[]`），GUI 启动打开"列表第一个加载成功的"——上次打开的 wf 一旦加载失败（JSON 坏/路径失效）就静默漂移到别的条目。改为显式记录：

1. **engine/config.js `rememberWorkflow()`**：加一行 `cfg.lastOpened = relativizeHome(fp)`（saveLocalConfig 整体写回，其它键自然保留）。
2. **index.js GET /api/workflows**：响应每行加 `last: true` 标记——用 `path.resolve(expandHome(cfg.lastOpened))` 对比行 path（normalizePath 归一后比较，防盘符大小写/分隔符差异）。
3. **web/src/App.svelte 初始化**：`wfList.find(w => w.last && w.name) ?? wfList.find(w => w.name)`——优先上次打开的，失效回退现有行为。
4. local-config.json / local-config.example.json 各加 `"paths": []`（见下）与实际 lastOpened 字段由代码写入，不手填。

## 二、paths 数组 + 启动前逐路径 git pull

1. **local-config.json 与 local-config.example.json** 新增 `"paths": []`。
2. **新建 tools/preflight.js**（一次性脚本，`node --check` 可验）：
   - 复用 `engine/config.js` 的 `loadLocalConfig()`（ESM import，tools/ 下已有先例）
   - 逐路径：展开 `~` → 目录不存在/非 git 仓库（`git rev-parse --is-inside-work-tree`）→ ⚠ 警告跳过；是仓库则 `git pull --ff-only`（execSync timeout 30s）→ 打印 `✓ <路径> (<分支>): Fast-forwarded/Already up to date` 或 `⚠ 失败原因`
   - **失败不阻断启动**（exit 0，只打警告）——控制台可用性优先于 git 状态；`--ff-only` 防意外 merge commit 落在工作区
3. **start.cmd**：`cd /d "%~dp0"` 后、`node index.js` 前插入 `node tools\preflight.js`。

## 验证（遵守 AGENTS.md：不连远程服务器；git 实测全部在 .tmp 本地仓库）

1. `node --check tools/preflight.js`；`node tools/verify-dryrun.js` 全绿；web 构建
2. preflight 实测（.tmp 本地 git 仓库 init+clone 两份，改源再 pull）：Fast-forward 生效、非 git 目录与不存在目录警告跳过、paths 为空直接通过；测完删临时仓库
3. GUI 实测（临时 wf，用后 forget+删）：打开临时 wf → local-config lastOpened 落盘正确 → 刷新页面自动打开该临时 wf
4. 按约定提交（含 buglog 记录）
