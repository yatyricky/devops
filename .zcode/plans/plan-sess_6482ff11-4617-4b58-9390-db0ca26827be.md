# systemd.run is-active 输出 boolean + 卡片原始输出展示 + TriSwitch 四值三态确认

## 一、is-active 输出 boolean

1. **engine/nodes/remote.js**：
   - 导出纯函数 `mapIsActiveState(out)`：trim 后 `active`→true、`failed`→false、其余（inactive/activating/unknown/空）→null
   - systemd.run 定义：`outputs: []` → `dynamicOutputs: "systemdActive"`（action 切换时出口自动出现/消失，下游死边清理联动——无冗余原则）
   - run：is-active 分支捕获原始 stdout（activeRaw）；任务收尾 `ctx.markNodeOutput?.(node.id, activeRaw)` 上报原始输出；`return action === "is-active" ? { active: mapIsActiveState(activeRaw) } : undefined`（is-active 的非零退出码保持不抛错）
2. **engine/rules.js effectiveOutputs**：新分支 `"systemdActive"` → `data?.action === "is-active" ? [{ id: "active", type: "boolean" }] : []`（meta 白名单 dynamicOutputs 已透传）

## 二、卡片原始输出展示（通用通道，systemd 先用）

3. **engine/runner.js**：run 对象加 `nodeOutputs: {}`；ctx 加 `markNodeOutput(nodeId, text)`（随 run 持久化 + persistSoon）

## 三、TriSwitch 四值三态（确认 + 实现）

确认：值域 true/false/undefined/null 共 4 种，UI 3 态——**undefined 与 null 共享空轨**。
10. **web/src/TriSwitch.svelte**：`class:unset={value == null}`（宽松相等同时覆盖 undefined/null）、title 判定同步；点击循环不变（null/undefined→true→false→true…）
