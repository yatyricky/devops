# Struct From JSON：shape 语义静态化二轮（可推导→自动出口；shape=契约；编辑期报错）

## 语义（用户定案）
- **输入可推导**：① 无 shape → 出口自动 = 派生 JSON 的字段（编辑期确定）；② 有 shape → shape 必须 ⊇ 派生字段（键存在+类型一致），否则**编辑状态报错**（卡片红框 + errline 文案 + 运行门禁拦截）
- **输入运行时**（不可推导）：必须定义 shape（空 = **编辑状态报错** + 门禁拦截）；运行时 JSON ⊄ shape → 运行时报错（已有子集校验）

## 一、共享推导核心（engine/rules.js 新增导出）
`deriveJsonText(env, nodeId, depth=0)`：fromjson 的 json 输入口编辑期字符串推导（纯数据驱动，双端单源）：
- `node.data.lit.json` → 返回
- json 口入边 → 源节点：`string.const`(data.value)、`string.join`/`path.resolve`（全部段可推导 → 拼接，~ 不展开）、`select.one`(pick 转发)、`struct.split`(struct 口透传) → 递归；其余/不可解/环 → undefined

## 二、effectiveOutputs fromJsonShape 分支改写（rules.js）
- shape 非空（有 key 的字段存在）→ 出口 `structShape(shape)`（shape=契约，现状语义）
- shape 空 → `deriveJsonText` 可推导 → 出口 `structShape(派生字段)`；不可推导 → `[]`（无出口）

## 三、编辑期问题判定（rules.js 新导出）
`fromjsonShapeProblem(node, env)`：
- 不可推导 + shape 空 → 「输入为运行时数据，必须定义 shape」
- 可推导 + shape 空 → null（1a 自动出口）
- 可推导 + shape 定义 → 逐派生字段查 shape：缺失/类型不符 → 报错文案（1b 超集校验）
- 消费端：**validateTaskRunnable**（engine/workflow.js）加 fromjson 分支（门禁拦截）；**DevNode cardError** 分支（经 types.js re-export，App context 传图）——红框（cardError 现成通道）+ shape 编辑器区 errline 文案

## 四、run 清理

- markNodeOutput 保留（原始输出 textarea 通道）
