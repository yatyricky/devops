# 排查结论 + 修复：selector pick 指向未选入源 → 静默回退残留 alias 连错服务器

## 根因（xlgbis.json 只读事实链）

1. **你的 selector 当前 pick="in3"**（不是 tencent-shanghai 那路）——三条入边：in1=makeq7031（tencent-shanghai）、in2=make9dgn2（dogyun-hongkong）、in3=maketvce1（dogyun-schlist）。GUI 第三行 radio 亮着（dogyun-schlist）。
2. **in3 的源 maketvce1 不在 LS-status 任务选点里**（任务只含 makeq7031/make9dgn2）→ 引擎执行时 maketvce1 未运行 → in3 口的值为 undefined。
3. **缺陷 A（selector run 校验失效）**：`pick in inputs` 检查被「键存在但值 undefined」骗过（引擎对未执行源也填了键）→ selector 静默输出 `{value: undefined}` 而非报错。
4. **缺陷 B（ssh.session 静默回退，最危险）**：alias 输入口已连线但值为 undefined 时，run 回退到卡片残留的 `data.alias="dogyun-hongkong"` → 连错服务器。这次被你填的指纹锁拦下（Host Key MISMATCH），否则就直接连上了。

「log 里为什么是 dogyun-hongkong」：它不是 selector 选出来的，是 ssh.session 卡片上残留的旧 widget 值。tencent-shanghai 那路（in1）根本没被 pick。

## 修复（引擎两处，各几行）

1. **engine/nodes/util.js selector run**：`pick in inputs` 改为 `inputs[pick] === undefined` 也报错——「所选输入 in3 未提供值（源未选入任务或未连线）」，把静默变明确失败。
2. **engine/nodes/remote.js ssh.session run**：alias/fingerprint 改「口已连线（`"alias" in inputs`）即不回退 widget」——连线但值为空 → 报「alias 输入口已连线但未提供值（检查上游 selector/split）」，杜绝连残留值。

## 验证

1. node 只读脚本跑 `validateTaskRunnable(xlgbis, "LS-status")`：确认对当前 wf 报「in3 依赖 maketvce1 未选入」（若已报则运行前门禁本会拦，用户跑时应为别的状态；若没报则另修）
2. verify 补断言：selector pick 取不到值 → run 抛错；ssh.session 连线口 undefined → 不回退 widget
3. 3199 独立实例复刻链实测：in3 指向未选入源时任务失败且错误信息明确
4. buglog 记 BUG + 提交；devops-wfs 全程只读、3010 不碰
